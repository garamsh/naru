# Proxy

What `naru-proxy` is and how a Machine is reached: the stable names, the aliases uses publish, the routes orch pushes, the forwarding over the host mesh, and the LAN's way in.

Everything below is built: `naru-proxy`, the exposure, orch's names, aliases and push, a move's change of a route, hostd's `PUT /v1/routes` and the ingress.

## Current decisions

- **Stable names** ([ADR 0112](./adr/0112-a-machine-is-reached-by-a-stable-name-through-naru-proxy-which-terminates-tls-reads-the-routes-orch-pushes-to-its-host-and-forwards-over-the-mesh-amending-adr-0085-items-3-5-and-6.md) item 1, [ADR 0120](./adr/0120-a-machines-stable-name-is-one-m-label-under-the-shared-garam-run-zone-and-naru-takes-no-alias-in-the-zone-superseding-adr-0112-items-1-and-3-in-part.md)).
  - **The forms.** A Machine's default service is `m-<id>.<zone>`, and its other services are `m-<service>--<id>.<zone>` (`lib/machineapi.StableName`); a service's name is at most 43 characters, so the name stays one label. The zone is orch's `--machine-zone`, `garam.run` for the coordinator's fleet.
  - **Why this form.** Each name is one label, so one wildcard certificate, `*.garam.run`, covers every name, and no name reveals a caller or a Machine's name. The zone is shared: in garam.run the `m-` labels are naru's and the `c-` labels cowork's, and `garam.run` is on the Public Suffix List, so every name under it is its own site.
  - **Moves.** A move never changes the name. The Machine API reports it as the `address`.
- **Services.** A Machine's `services` (`name`, `port`, `protocol` `http` or `tcp`, optional `proxyProtocol: v2`) are all a proxy reaches; the first is the default. `http` carries HTTP/1.1, HTTP/2 and WebSocket. `tcp` is TLS from the client, terminated by SNI, and plain TCP to the Machine.
- **Aliases.** A use publishes `PUT /machines/v1alpha1/aliases/{hostname}` (Machine and service), and the first caller to create a hostname holds it ([ADR 0112](./adr/0112-a-machine-is-reached-by-a-stable-name-through-naru-proxy-which-terminates-tls-reads-the-routes-orch-pushes-to-its-host-and-forwards-over-the-mesh-amending-adr-0085-items-3-5-and-6.md) item 3).
  - **Not in the zone.** naru answers only its stable names in the zone, which other names share, and refuses an alias there with 422 ([ADR 0120](./adr/0120-a-machines-stable-name-is-one-m-label-under-the-shared-garam-run-zone-and-naru-takes-no-alias-in-the-zone-superseding-adr-0112-items-1-and-3-in-part.md) item 2).
  - **In a granted domain.** An alias ends in a domain the operator granted the caller (`PUT /v1/callers/{name}` with `aliasDomains`, operator and root) and brings a certificate and key for the hostname.
  - **The key** is never read back: `GET` shows `<set>`. It goes only to the proxies' hosts.
  - **Deleting.** An alias goes with its Machine.
- **`naru-proxy`** is the binary of the unit `proxy/` (`proxy/cmd/naru-proxy`, `/bin/naru-proxy` in the image). Init runs it as user and group 6003 on each host whose configuration has `spec.proxy`, with `CAP_NET_BIND_SERVICE` as its one ambient capability and an open-file limit of 9216, two descriptors for each connection it may hold and room for the rest ([config.md](./config.md)); a site runs at least two.
  - **TLS.** It terminates TLS 1.2 and 1.3 (nothing older) on `spec.proxy.listen`, port 443 on every address by default, with the zone's wildcard certificate (`spec.proxy.certificate`, and the key as a `spec.files` entry) and each alias's own pair from the table.
  - **Lookup.** The SNI chooses the route and the certificate: an alias's own, else the zone's when it covers the name. A handshake without an SNI, for a name with no route, or for a name no certificate it holds covers, is refused with the alert `unrecognized_name`, and no byte reaches a Machine. An `http` route offers `h2` and `http/1.1` by ALPN and carries HTTP/1.1, HTTP/2 and WebSocket (the HTTP/1.1 upgrade); a `tcp` route offers no ALPN and is routed by the SNI alone.
  - **421.** Each `http` request is routed by its own Host or `:authority` (case and a trailing dot aside), which must be a name the connection's certificate covers and that has an `http` route, else 421 Misdirected Request, so HTTP/2 connection coalescing under the wildcard reaches each Machine and a client that reused a connection for another name retries on a new one.
  - **Forwarding.** It connects to the Machine's private address at the service's port from its host's mesh address (the routes file's `meshAddress`; the kernel chooses when the file has none), in 5 s at most. On `http` it keeps the Host, adds `X-Forwarded-For` (the client's address; one the client sent is dropped), `X-Forwarded-Host` and `X-Forwarded-Proto: https`, drops the client's `Forwarded` and `X-Real-IP`, and answers 502 when the Machine does not answer. A route with `proxyProtocol: v2` gets the PROXY protocol v2 header of the client first: on `tcp` once per connection, on `http` on a connection to the Machine used for that client's request alone. A client's connection, a `tcp` service's or an upgraded WebSocket among them, is closed when it has carried nothing in either direction for 5 minutes, so a service that only pushes keeps its client; an `http` connection is also closed 5 minutes after its last request.
  - **Connections.** It holds at most 4096 client connections at once and 128 from one address (`lib/wire`'s `ProxyMaxConns` and `ProxyMaxPerSource`, hostd's exposure proxy's figures); one over either is closed at its accept, and a connection gives its slot back when it closes.
  - **Answers without dialling.** A route that is not `running` is answered 503 with `Retry-After: 5` on `http` and closed on `tcp`, and so is every route once the table is older than `--route-max-age`.
  - **Redirect.** On `--redirect-listen` (`0.0.0.0:80` from init) it answers plain HTTP with 308 to `https://` on the request's host, its port dropped, and the same path and query, and 400 to a request that names no host. Its connections count against the same limits as the TLS listeners' and are closed by the same idle rule.
  - **Health.** `GET /healthz` on `127.0.0.1:7480` answers the revision of the table it forwards on (0 before the first), when hostd took it, and whether it is older than `--route-max-age`, for hostd's candidacy for a proxy exposure.
  - **Credentials.** It holds no credential but the certificates it serves.
- **Routes** ([ADR 0112](./adr/0112-a-machine-is-reached-by-a-stable-name-through-naru-proxy-which-terminates-tls-reads-the-routes-orch-pushes-to-its-host-and-forwards-over-the-mesh-amending-adr-0085-items-3-5-and-6.md) items 5 and 6, [ADR 0119](./adr/0119-the-proxy-role-is-the-operators-grant-and-orch-tells-every-host-the-proxy-peers-and-the-mesh-pool-with-its-peers-superseding-adr-0112-items-5-6-and-7-in-part.md) items 1, 2, 4 and 5).
  - **The proxy role.** A proxy host is an admitted host that holds the operator's grant, `proxy` in its inventory record (`naructl host grant-proxy`, [orch.md](./orch.md) §Proxy grant), and whose `GET /v1/host` reports a proxy. Only a proxy host is sent the table, with its alias keys, and marked `proxy` on the peers. A host that reports a proxy without the grant is sent neither, and the leader logs it and appends `route.proxy-not-granted` once per host in its term. `spec.proxy` decides whether a host runs a proxy, and the grant whether orch trusts it with the role.
  - **The table.** Each stable name and alias with the Machine's private address, its services, whether it runs, and an alias's certificate and key. It carries the revision of orch's store at which orch read the Machines and the aliases together, so it never mixes two states of the store.
  - **The push.** The leader puts the whole table to every proxy host, healthy or not (`PUT /v1/routes`, provisioner, leader token), on each write to the Machines or the aliases and every `--network-interval`, to all of them at once. A lower revision is refused, and so is a table whose `sentAt` is more than 4 s behind the host's clock: orch abandons a push not answered in 2 s, and 2 s more allow for the skew between clocks kept from `spec.time`; the refusal, 409 `late-table`, names the difference the host saw. The proxy writes the revision it has loaded to a file hostd reads, and hostd answers it; orch keeps the highest per proxy host under `/naru/orch/route-acks/<host>`, created at revision 0, with the time of the push and the longest max age the host reported, before each push. The time is taken, and the hosts are tracked, before orch reads the store for the table, so a table older than a commit is sent with a time before it, and a host that may take it is in the set a delete after the commit waits on. A route that does not check, or a name two routes claim, is left out, and orch logs it once.
  - **On the host.** hostd writes the table it took, with the time it took it (`receivedAt`, the host's clock) and the host's mesh address, as `lib/hostapi.RoutesFile` to `/var/lib/naru/proxy-routes/routes.json` (0640, the proxy's group; the directory is init's, root's with group 6003, on the data disk so a restarted proxy keeps its table while it is young). The proxy (built) checks the file every second and loads a new version: a file that is missing or does not parse, has no `receivedAt` or a mesh address that is not IPv4, or holds a lower revision, leaves the table it had and is logged once. A route that fails `lib/hostapi`'s `Route.Check` (a hostname that is not a lowercase DNS name; an address that is not IPv4, or is loopback, unspecified, link-local, multicast or broadcast; a port, protocol or PROXY version out of range; an alias pair that does not load or cover its name), and every route of a name given twice, is dropped alone and logged, and the rest is loaded, so one tenant's bad alias does not stop the routing of every other name: a drop removes a name and never sends a client to another address. Orch refuses an alias, and hostd a table, by the same check, so a proxy drops only what reached it past both. A `receivedAt` after the proxy's clock, which has stepped back since hostd wrote it, is taken as the time of the load. A table of the same revision is taken, so each push keeps it young. It writes the revision it loaded to `/run/naru-proxy/revision`, which hostd reads.
  - **When orch is away.** A proxy forwards on its last table for `--route-max-age` (default 1 hour, at most 24 hours, which init and hostd refuse to exceed; `spec.proxy.routeMaxAge`) after hostd received it, by `receivedAt`, then answers 503 (built). The leased LAN addresses drop within 15 s of orch's loss (ADR 0085 item 5), so routing through them does not survive it; each proxy also listens on its host's own LAN address, and a site whose DNS lists those keeps routing for up to `--route-max-age`. The Machines keep running.
  - **Moves.** A move's commit changes the Machine's entry, its private address to the target's, in the same transaction that rebinds it, and the move deletes the source's microVM under the rule below. A Machine that is not running is answered 503 with `Retry-After: 5`.
  - **No stale route reaches another Machine.** Each entry names the Machine's `id`. Orch deletes a microVM whose address a route named only when every proxy host has acknowledged a revision that no longer names the address, or, for a proxy that has not, once that proxy's own `--route-max-age` plus 8 s (`lib/hostapi.RouteRelease`) has passed since that revision; the Machine's record keeps the revision and the time of the pass that first found its microVM to delete, so a new leader waits on the same, and an address mvmd reuses is never in a table a proxy still forwards on ([ADR 0112](./adr/0112-a-machine-is-reached-by-a-stable-name-through-naru-proxy-which-terminates-tls-reads-the-routes-orch-pushes-to-its-host-and-forwards-over-the-mesh-amending-adr-0085-items-3-5-and-6.md) item 6 and its errata).
    - **The 8 s.** The 2 s of a push; the skew of the host's clock against the sender's, which the host's refusal counts once and its proxy's age counts again; and the skew between the orch member that sent the table and the one that recorded the time the delete waits from.
    - **The max age.** Each host reports its proxy's on `GET /v1/host`, and orch keeps the longest with the acknowledgement; none is the 1 h default. A negative value or one above 24 h is taken as 24 h, never as the default, and the leader logs it and appends `route.max-age-clamped` once per host and value in its term.
    - **The set waited on.** The admitted hosts with an acknowledgement. A removed or abandoned host leaves it, since it is out of every peer list and so out of the mesh its proxy forwards over. A host that answers with no proxy, or with one but no grant, is sent no table, and its acknowledgement is deleted once its last push plus its max age plus 8 s has passed ([ADR 0119](./adr/0119-the-proxy-role-is-the-operators-grant-and-orch-tells-every-host-the-proxy-peers-and-the-mesh-pool-with-its-peers-superseding-adr-0112-items-5-6-and-7-in-part.md) item 4).
- **What reaches a Machine.** Of sources in `meshPool` (hosts' own addresses), hostd's `inet naru` accepts to the host's microVMs only the mesh addresses of the peers orch marks `proxy` in `PUT /v1/peers`, the proxy hosts, and drops and counts every other source in the pool, which orch puts with the peers, so no other host on the mesh, nor a relay's spoke behind a peer, reaches a Machine directly ([ADR 0119](./adr/0119-the-proxy-role-is-the-operators-grant-and-orch-tells-every-host-the-proxy-peers-and-the-mesh-pool-with-its-peers-superseding-adr-0112-items-5-6-and-7-in-part.md) item 3). The host's own proxy reaches them from the host, which the rule does not judge; traffic between microVMs of a network across hosts is not touched and stays under the per-network sets; mvmd's ingress, fixed at create, admits orch's mesh pool to each service's port only, and orch keeps the address the host gave the microVM as the Machine's private address. Egress is the Machine's `networkPolicy` ([ADR 0112](./adr/0112-a-machine-is-reached-by-a-stable-name-through-naru-proxy-which-terminates-tls-reads-the-routes-orch-pushes-to-its-host-and-forwards-over-the-mesh-amending-adr-0085-items-3-5-and-6.md) item 7).
- **The LAN's way in is the exposure lease** (built; [ADR 0112](./adr/0112-a-machine-is-reached-by-a-stable-name-through-naru-proxy-which-terminates-tls-reads-the-routes-orch-pushes-to-its-host-and-forwards-over-the-mesh-amending-adr-0085-items-3-5-and-6.md) item 8).
  - **The exposure.** An operator declares `PUT /v1/proxy-exposures/{id}` (operator and root): any pool and ports 443, and optionally 80, which redirects ([orch.md](./orch.md)).
  - **The lease.** Candidates are proxy hosts, holding the operator's grant ([ADR 0119](./adr/0119-the-proxy-role-is-the-operators-grant-and-orch-tells-every-host-the-proxy-peers-and-the-mesh-pool-with-its-peers-superseding-adr-0112-items-5-6-and-7-in-part.md), erratum), with a LAN interface and whose `GET /v1/host` reports `proxy.healthy`, which hostd keeps from this health check, asked every 5 s and false only after 3 failed asks in a row ([host.md](./host.md)). ADR 0085's lease and failover apply, with its items 3, 5 and 6 amended for this kind (any pool, the proxy's health as the candidate rule, a redirect to the local proxy).
  - **On the holder.** The holder redirects 443 to the port of its proxy's first TLS listener and 80 to the redirect listener, in `inet naru`, for flows on the LAN interface to the leased address ([host.md](./host.md)).
  - **Several addresses.** One exposure per proxy host gives an address on each while both run, and both on one host when the other is lost: orch spreads proxy exposures over the candidates before it leases them ([ADR 0117](./adr/0117-proxy-exposures-are-spread-over-the-proxy-hosts-one-address-to-a-host-while-there-are-hosts-enough-superseding-adr-0112-item-8s-several-addresses-in-part.md)).
  - **What naru does not run.** The zone's DNS and any path from the internet are the site's.

## Rationale

- [ADR 0112](./adr/0112-a-machine-is-reached-by-a-stable-name-through-naru-proxy-which-terminates-tls-reads-the-routes-orch-pushes-to-its-host-and-forwards-over-the-mesh-amending-adr-0085-items-3-5-and-6.md): why single-label names with the `id`, why the proxy terminates TLS (and not SNI passthrough), why orch pushes through the host API (and not a proxy credential), why an address is released only on every proxy's acknowledgement, why only proxy hosts reach Machines, why a proxy exposure is a resource of its own, why the proxy runs on hosts (and not as Machines, in garam's cluster, or on every host), and how the lease fits; fly-proxy and E2B's client proxy weighed.
- [ADR 0113](./adr/0113-hosts-form-a-wireguard-mesh-with-an-address-each-hosts-that-cannot-be-reached-dial-out-to-relays-and-orch-rotates-every-hosts-key-amending-adr-0045-item-5-adr-0048-item-5-and-adr-0049-item-6.md): the mesh address the proxy forwards from.
- [ADR 0117](./adr/0117-proxy-exposures-are-spread-over-the-proxy-hosts-one-address-to-a-host-while-there-are-hosts-enough-superseding-adr-0112-item-8s-several-addresses-in-part.md): why proxy exposures are placed together in one sequential stage and spread one address to a host, where rendezvous hashing alone would put two addresses on one of two hosts half the time.
- [ADR 0119](./adr/0119-the-proxy-role-is-the-operators-grant-and-orch-tells-every-host-the-proxy-peers-and-the-mesh-pool-with-its-peers-superseding-adr-0112-items-5-6-and-7-in-part.md): why the proxy role is the operator's grant and not the host's report (the table carries every alias key, and the mark reaches every Machine), why the proxy set and the mesh pool go with the peers, how a host that leaves the role is waited out, and why a max age is capped.
- [ADR 0120](./adr/0120-a-machines-stable-name-is-one-m-label-under-the-shared-garam-run-zone-and-naru-takes-no-alias-in-the-zone-superseding-adr-0112-items-1-and-3-in-part.md): why the stable names are `m-` labels under the shared garam.run zone, and why naru takes no alias there.

## Open questions

- **Waking a stopped Machine on traffic**, as E2B's client proxy does. A Function service needs it.
- **ACME** (#395). The zone's certificate is a file. DNS-01 issuance on the garam.run zone needs a token scoped to that zone, which is not yet granted.
- **Aliases in the zone** wait for a naming policy of garam.run as a whole.
- **A private address kept across moves**, routed to whichever host holds the Machine. It is not taken: uses reach Machines by name.
- **Deltas.** The whole table is pushed. Deltas wait for a table large enough to cost.
