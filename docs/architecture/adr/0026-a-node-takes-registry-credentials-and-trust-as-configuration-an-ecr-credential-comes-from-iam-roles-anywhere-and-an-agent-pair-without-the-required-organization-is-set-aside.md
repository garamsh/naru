# ADR 0026: a Node takes registry credentials and trust as configuration, an ECR credential is renewed through IAM Roles Anywhere with the agent's pair, the image carries a pinned root bundle, and a kept agent pair without the required organization is set aside

> Status: accepted
> Date: 2026-11-13

Append-only: once merged, the body below is not rewritten. A fact later found wrong is corrected in an appended note, not edited out; a revised decision is a new ADR that supersedes this one.

Drafted for garamsh/naru#65, part of garamsh/naru#62 (E4) and garamsh/aurora#749. It amends [ADR 0018](./0018-a-nodes-configuration-is-a-base-and-numbered-revisions-stored-on-the-data-disk-and-changed-by-merge-patch.md) by reference: its body is not edited, and what it says of the classes and the keyed lists holds with this decision added. It rides on [ADR 0008](./0008-a-node-reads-its-configuration-and-network-from-a-cloud-init-nocloud-drive.md), which is how the configuration reaches a Node, and on mvmd's registry section at commit `d189133bba8d842d2bcb20046f39fe03161efeb1` (`credentials_file`, `ca_file`, `credential_helpers`).

## Context

- **A Node pulls from a registry that wants a credential and a certificate it trusts.** Until now the only registry was the test image's, trusted through mvmd's `SSL_CERT_FILE`, and the image carried no root authorities at all, so mvmd could pull from no public registry. aurora keeps its images in ECR, which wants a password that lasts twelve hours and a TLS chain that ends in a public root.
- **mvmd reads three things for a registry.** `credentials_file` (a Docker-style JSON of host to username and password), `ca_file` (a PEM bundle added to the roots it trusts) and `credential_helpers` (a host to the name of an executable `docker-credential-<name>` that mvmd runs as `get`, with its own environment). mvmd checks that the named files exist when it starts, and reads credentials and CA again at each pull. Its `validate()` refuses a registry section that names none of the three.
- **An ECR credential is made by a helper that calls AWS.** `docker-credential-ecr-login` asks the AWS SDK for a token; the SDK finds its credentials in the environment and the shared config file. IAM Roles Anywhere gives a certificate holder temporary credentials: `aws_signing_helper credential-process` signs a request with a certificate and key and prints the credentials, and the SDK runs it from a `credential_process` line of a profile. Sessions last 900 s here.
- **The Node already has a certificate that fits.** gaon's Node Agent keeps its pair in `--cert-dir`, as one file `node-agent.pem`: the certificate, then the PKCS#8 key, `0600`. The signer approves a request only with `O=gaon:nodes`, and the aurora role requires that organization in the certificate's subject.
- **The first agent pairs did not have it.** A data disk that kept a pair from before the signer set `O=gaon:nodes` has a pair that the API server still accepts and AWS refuses. The agent asks for a new pair only when it has no valid one, so it would never ask.
- **The image's Go programs are built with `CGO_ENABLED=0`** ([image.md](../image.md)). `aws_signing_helper` cannot: it links `miekg/pkcs11`, which needs cgo, and its module needs a newer Go than the others.

## Decision

1. **`spec.registries`** is a list of `{host, ca, credential}`, a keyed list keyed by `host` ([ADR 0018](./0018-a-nodes-configuration-is-a-base-and-numbered-revisions-stored-on-the-data-disk-and-changed-by-merge-patch.md)). `host` is a registry's name as an image reference spells it (a host name or an IP address, with an optional port). `ca` is optional, a PEM bundle of the authority that signs the registry's certificate. `credential` is optional and is either `{username, password}` or `{helper}`, the name of a `docker-credential-<name>` program; it is refused when it names both, or a helper name with a character outside letters, digits, `-`, `_` and `.`, or a username without a password or the reverse. A host is not listed twice. A breach refuses the configuration, naming `spec.registries[i].<field>`.
2. **`spec.aws`** is `{region, trustAnchorArn, profileArn, roleArn, certificate, key}`, all required and refused when one is missing: the region, the three ARNs of IAM Roles Anywhere, and the absolute, clean paths of the certificate and key files of the pair that signs. `naructl` defaults the two paths to the Node Agent's `node-agent.pem`, the same file for both.
3. **init writes three files under `/run/naru`, after `spec.files` and before the time and the certificates**, and never writes them again except by apply:
   - `registry/credentials.json`, `0600`, always. It holds `{host: {"username": …, "password": …}}`, mvmd's format, for every host with a username and password, and `{}` otherwise, because mvmd refuses a configuration that names a missing file.
   - `registry/ca.pem`, `0644`: the concatenation of every `ca`, in list order; removed when no registry has one.
   - `aws/config`, `0644` (it names files and ARNs, not secrets): a `[default]` profile with the `region` and a `credential_process` of `aws_signing_helper credential-process --certificate … --private-key … --trust-anchor-arn … --profile-arn … --role-arn … --region …`; removed when `spec.aws` is absent.
   A failure to write them refuses the boot: a Node that cannot pull is not a Node that runs.
4. **The layout points mvmd at them.** `naructl` writes mvmd's `registry` section: `credentials_file` always, `ca_file` only when some registry has a `ca` (the file exists then), and `credential_helpers` with a host to a name for each registry that names a helper. mvmd's environment is `PATH=/bin:/run/bin`, so that `docker-credential-<name>` is found in the image or in `/run/bin`, where `spec.files` can put one (`0755`). With `spec.aws` it also has `AWS_CONFIG_FILE=/run/naru/aws/config` and `AWS_REGION`. The test image's `SSL_CERT_FILE` is gone: the registry service's authority is a `spec.registries` entry like any other.
5. **The ECR helper and the signing helper are in the image**, as `/bin/docker-credential-ecr-login` and `/bin/aws_signing_helper`, built from the pins `image/ecr-login/pin.env` (v0.12.0, commit `7ff7d6bd7a06408ddb9646c9ebccf97dbd190d55`, Go 1.26.11) and `image/rolesanywhere/pin.env` (v1.8.6, commit `f17999e83885205544bda00553ffb907a16bf862`, Go 1.27.3), each checked against its commit as the other builds are, and covered by `make image-repro`. A registry whose `credential` is `{helper: ecr-login}` and a `spec.aws` give a Node an ECR credential that renews itself: mvmd runs the helper at each pull, the SDK runs `aws_signing_helper` for its session, and the pair is read from the data disk each time.
6. **`aws_signing_helper` is linked statically with cgo**: `-linkmode=external -extldflags=-static`, tags `netgo,osusergo`. This is a deviation from `CGO_ENABLED=0`, with the static C-built `mke2fs` of [ADR 0011](./0011-mkfs-ext4-is-a-static-mke2fs-built-from-the-pinned-e2fsprogs-release-and-installed-in-the-image.md) as the precedent that the image holds a static program built with a C toolchain. The linker warns that glibc's `dlopen` needs the libraries of the build; the warning is harmless, because the helper's PKCS#11 path, the only one that would `dlopen`, is not used: it is given files. The image's static check (`file`) covers it.
7. **The image carries a pinned root bundle** at `/etc/ssl/certs/ca-certificates.crt`, `0644`: curl's `cacert.pem` at a dated release, `https://curl.se/ca/cacert-2026-11-05.pem`, 118 certificates, pinned by URL and SHA-256 in `image/cacert/pin.env` and checked after the download. The date is in [image.md](../image.md), and a release's notes say it, so an operator knows which roots a release trusts. A new bundle is a new pin and a new release, as any other input.
8. **The test image appends a throwaway root.** `make` takes `TEST_ROOT`, a PEM file, empty by default. When it is set, the bundle is the pinned one with that file appended, and the stamp of the bundle includes its hash, so building without it rebuilds the pinned bundle. `make test-qemu` makes a root (`naru-testroot`), builds the image with it, and gives the test the root's directory so that it can sign the registry's certificate with it. No release sets it, and `make image-repro` builds the release image, with no `TEST_ROOT`.
9. **A kept agent pair without the required organization is set aside.** A service of the layout may carry `keptPair: {file, organization}`; init, just before it starts that service, reads the first certificate of `file`, and when its subject has no `organization` renames the file to `<file>.o-less`, replacing an earlier one. A file that is missing or is not a certificate is left alone. A failure to rename is logged and the boot goes on. The layout gives `gaon-node-agent` `keptPair: {<cert dir>/node-agent.pem, gaon:nodes}`, so the agent finds no pair and asks for another with its bootstrap token. The required organization is data of the layout, not of init: init knows no gaon name.
10. **Live class, no restart.** `spec.registries` and `spec.aws` are in the live class of ADR 0018: an apply that changes them has init write the three files again (the `write-registries` step) and restarts no service, because mvmd and the SDK read them at each use. Two changes need more, both in files of the layout and not in init's: the first `ca` or the first helper host of a Node whose mvmd configuration does not name `ca_file` or the helper changes `/run/mvmd/config.json`, a `spec.files` entry that restarts mvmd; adding `spec.aws` to a running Node changes mvmd's `env`, so the service differs and apply restarts mvmd (the one restart this decision can cause; a MicroVM's supervisor is outside mvmd's cgroup, so the MicroVM stays up, [image.md](../image.md)).
11. **Passwords read as `REDACTED`, a patch that sends `REDACTED` is refused unless the stored password is that literal, and a patch that omits the password keeps the stored one.** The Node API's `GET /v1/config` replaces every `spec.registries[].credential.password` with `REDACTED`, as it does the other secrets ([ADR 0017](./0017-the-node-api-is-served-by-init-over-mutual-tls-from-its-own-authority-and-naructl-is-its-client.md)). The apply engine refuses a `REDACTED` password (`InvalidError` on `spec.registries[i].credential.password`) unless the stored password is that literal, as it does `spec.api.key`, the authorities' keys and private `spec.files`; a patch that names the registry and omits the password keeps the stored one. It never writes `REDACTED` over a real password.
12. **`naructl gen node`** takes `--registry host=H[,ca=FILE][,username=U,password=P][,helper=NAME]` (repeatable; `ca` is a file read when the user-data is written), and `--aws-region`, `--aws-trust-anchor`, `--aws-profile`, `--aws-role`, all four or none. It refuses a host that has both a credential and a helper. [config.md](../config.md) §Operator tooling lists them.

## Consequences

- A Node pulls from ECR with no secret on its disk: the pair is the Node Agent's, the sessions last 900 s, and a stolen session is useless in a quarter of an hour. What a disk does hold is the pair, as it did.
- A password in `spec.registries` is in the NoCloud drive and in the stored revisions of the configuration, as every value is. It is not shown by the Node API. A secret that must not be on the drive uses a helper.
- The image is larger by two programs of about 9.5 MB and 12 MB and a bundle of 200 KB, and `make image-repro` builds three more inputs.
- Roots are as old as the image. A root that a public registry moves to after the pinned date is not trusted until the pin moves; `spec.registries[].ca` is the stopgap.
- A kept pair set aside is not deleted: `<file>.o-less` stays on the data disk for an operator to read, and is replaced by the next one.
- The data disk of a Node whose agent already has a good pair is unchanged: the check reads and compares, and renames nothing.
- The cgo build needs a C toolchain and the static C library on the build host, the release's first such need beyond e2fsprogs (ADR 0011).

## Signs the decision was wrong

- A registry needs credentials that are not a username and password or a Docker helper (a token the operator rotates by hand and must not store): `spec.registries[].credential` then needs another form, and files that init writes for it.
- The set-aside rule is wanted for a file that is not an agent pair, or for a subject field that is not an organization: `keptPair` then needs a general check, and the rename is the wrong action.
- The bundle's age is regularly the cause of a refused pull: the answer is that the roots come from the Node's configuration or a feed, and the image carries a floor only.
- `aws_signing_helper` is released for `CGO_ENABLED=0`, or the dlopen warning turns into a failure: the static cgo link of item 6 goes, or the helper is built another way.
- Operators keep passwords in `spec.registries` after all and need them off the drive: the answer is that a Node takes a secret from somewhere that is not its configuration.
