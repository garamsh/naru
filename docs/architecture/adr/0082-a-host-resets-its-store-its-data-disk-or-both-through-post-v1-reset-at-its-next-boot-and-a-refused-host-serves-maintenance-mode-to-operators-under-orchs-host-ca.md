# ADR 0082: a host resets its store, its data disk or both through POST /v1/reset at its next boot, and a refused host serves maintenance mode to operators under orch's host CA

## Context

- **A host can be in a state no call repairs.** A refused boot starts no service, so the host API is down, and a store that holds a configuration the Node cannot run keeps refusing it at every boot. The only way out was a console or a new disk.
- **A reset has to survive its own reboot.** The data disk is mounted by init and by the services above it; a service cannot remove what it holds open, and init is the one that mounts it.
- **A refused host has no authority of its own to trust.** Its `spec.api` is not read, so it knows no CA, yet it must accept an operator and refuse a revoked one. What the installation left is the seed: orch's URL and the SHA-256 of orch's host CA.
- **A Node is a different case.** Its configuration comes from the operator and its disk holds no fleet identity; replacing it costs nothing the operator did not write down.

## Decision

**Reset and maintenance mode are the host's. A Node is replaced, not reset.**

1. **`POST /v1/reset` takes `{scope, confirm}` and needs the provisioner role.** `scope` is `store`, `data` or `all`. `confirm` must equal the host's ID, else 422 and nothing is done. The ID is `--host-id`, else the common name of `host.crt` beside `--host-key`, else the hostname; `GET /v1/host` reports it as `hostId`. A host started with no ID, reset marker or reboot function answers 501.
2. **The scopes.** `store` removes `config/store.yaml`, so the base runs as revision 0. `data` removes everything on the data disk except `config/` and `lost+found`. `all` unmounts the data disk, zeroes its first and last 1 MiB, formats it as a blank disk is formatted at a first boot and mounts it again.
3. **The reset is carried out by init at the next boot.** hostd writes `/var/lib/naru/config/reset.json` (`{"scope":...}`) atomically, answers 202, and after one second reboots the host by signalling init. If the reboot cannot be asked for, hostd removes the marker. Init, after the data disk mounts, reads and removes the marker before it acts, so a boot that fails half way is not asked again; a reset that fails is a refusal.
4. **A reset that would lock the host out is refused.** The pair that serves after a reboot is the one `chooseServing` picks (ADR 0077): the rotated pair `serving.pem` beside `--host-key` when it is not revoked, else the configuration's pair at `--cert`. `--host-key` is `/var/lib/naru/hostd/host.key`, on the data disk, so a reset of scope `data` or `all` deletes `serving.pem`, and the pair that serves after it is the configuration's alone. For those scopes hostd calls `checkOwnCertificates` on `--cert`, the check `chooseServing` makes of that pair, and answers 409 with the code `revoked-pair` when it is revoked; a list that cannot be had also refuses. Scope `store` keeps `serving.pem` and is not checked. A host that was rotated and whose configuration's pair is revoked therefore cannot be wiped until the configuration names a pair that is not.
5. **A refused boot enters maintenance mode.** Init's refusal path, after the boot returns an error, starts a derived service `naru-hostd` with `--maintenance`. It does nothing, and logs why, when hostd already started, when there is no anchor, when there is no revocation key, or when the network cannot come up (it tries the stored network-config, then the seed's, then DHCP, when the refusal came before the network). When the refusal came before the data disk was mounted, maintenance mounts it by its default label and mount point, without carrying out a reset, so that the stored anchor and network-config can be read; a disk that cannot be mounted is logged and leaves them unread. `lib/init/run` is unchanged.
6. **The trust anchor is orch's host CA by its fingerprint.** It is `spec.join.orch` or `spec.host.orch` of the seed's user-data, read leniently since the seed may be the reason for the refusal, with the revocation public key of the stored `config/maintenance.json`, which init writes at each successful boot. The seed's URL and fingerprint win; the stored key is used only if the fingerprint it was stored with matches. With no anchor or no key, maintenance does not start: it fails closed.
7. **hostd in maintenance mode.** It fetches orch's authority from a handshake verified by the fingerprint ([ADR 0059](./0059-orch-admits-a-host-that-boots-from-an-install-seed-allocates-its-machine-prefix-and-builds-its-configuration-from-one-fleet-profile.md)'s `orchapi.PinCA`), taking the chain entry whose SHA-256 matches, and retries every 5 s. It listens on TLS 1.3, requires a client certificate verified against that authority only, and checks the list of ADR 0062 in the handshake; a list it cannot have refuses every client. It serves `GET /v1/maintenance` (`hostId`, `reason`) and `POST /v1/reset`, behind the roles of ADR 0028, and nothing else. Its serving pair is the one `chooseServing` picks from `serving.pem` and the enrolled `host.crt` and `host.key` beside `--host-key`, and it refuses to start when that pair is revoked; with no enrolled pair it serves a self-signed one. The reset of maintenance mode is not checked against the configuration's pair, which a refused host cannot name.
8. **`naructl reset --scope --confirm`** calls the reset with the host client of `naructl host`.

## Consequences

- **A host has a way back from a refusal.** An operator under orch's authority resets the store (revision 0, the seed runs again) or the disk without a console.
- **The marker's path is one constant,** `wire.ResetMarker` in `lib/wire` ([ADR 0070](./0070-shared-constants-are-defined-once-in-the-leaf-module-lib-wire-one-rule-says-when-a-disk-is-blank-and-a-test-parses-what-the-layout-writes.md)); init's store directory and hostd's `--reset-marker` default both read it.
- **Limits.** A host that never enrolled is unreachable in maintenance mode. A refusal before the network, with no fingerprint on the seed and none stored, has no maintenance mode. A join-form seed carries no revocation key, so it has none until a successful boot has stored the anchor. A seedless host loses its anchor after scope `all`. The maintenance routes sit behind the roles of the host API, so an operator's certificate has the role of its organizational unit (ADR 0080). A refused boot logs `boot refused; no service of the configuration will start`, which stays true while maintenance mode runs.
- **A control-plane member is not removed first.** Removing an orch or etcd member before a wipe is out of scope; a wipe of such a host leaves its membership to the operator.
- **The QEMU test is written and not run.** `tooling/qemu/tests/reset_fleet_test.go` (store reset to revision 0, a wipe followed by a re-format, maintenance reached by an operator certificate and refused for a revoked one) was compiled with `go vet -tags qemu_real` only; it is deferred to the final check.

## Signs the decision was wrong

- Operators reset hosts they did not mean to: the confirmation by ID is too weak, and the call needs a second factor.
- Hosts are refused with no anchor in practice (a seedless host after `all`): the anchor belongs somewhere a wipe does not reach.
- A Node needs a reset: that says replacing it is too costly, and the Node API needs the call.
